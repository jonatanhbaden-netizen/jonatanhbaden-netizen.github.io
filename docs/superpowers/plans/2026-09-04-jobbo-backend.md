# Jobbo Demo 1 — Backend Implementation Plan (Plan 1 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A working Supabase Postgres backend for Jobbo — schema, row-level security, the rule-based matching function, the rationing rules that make "10 qualified applicants, not 400" true, and ~300 seeded Norwegian candidates matched against ~60 jobs.

**Architecture:** Everything lives in Postgres. Matching is a deterministic plpgsql function scoring a `(job, profile)` pair 0–100 with a Norwegian human-readable `reasons` array. Triggers recompute scores whenever a job or profile changes. The rationing rules (score ≥ 60 to apply, max 5 active applications, shortlist capped at 10) are enforced by a `BEFORE INSERT` trigger on `applications`, not by the UI — so the seed generator exercises the same rules real users will. No Edge Functions, no LLM.

**Tech Stack:** Supabase (Postgres 17, Auth, RLS), plpgsql, pgTAP for tests, Supabase CLI + Docker for local dev, Node 24 + `@supabase/supabase-js` for the seed generator.

**Spec:** `docs/superpowers/specs/2026-09-04-jobbo-demo-design.md`

## Global Constraints

- **Region:** `eu-west-1` (EU data residency — see spec §Honest constraints #3).
- **Local-first:** all development runs against `supabase start` (local Docker). The hosted project is created only in Task 10.
- **Migrations are append-only once pushed.** Until Task 10 nothing has been pushed, so Tasks 4–6 legitimately append to the same `0003_matching.sql` file. After Task 10, never edit an existing migration — add a new one.
- **Language:** all enum values, error messages, and `reasons` text are Norwegian bokmål. Column and function names are English.
- **Skills vocabulary:** lowercase canonical strings only. No synonym handling (spec §7).
- **Kvalifisert threshold:** `score >= 60`. This constant appears in the rationing trigger and in `my_matches` — keep both in sync.
- **Weights sum to exactly 100:** skills 35, nice 5, utdanning 15, erfaring 15, sted 15, språk 10, oppstart 5.
- **No status changes by machine.** Only an employer changes `applications.status`. Nothing auto-rejects (spec §Honest constraints #3).
- **Service-role key never leaves the local machine.** It is used only by `supabase/seed/generate.mjs`, read from env, and must never appear in `web/`.

## Spec deviations resolved in this plan

| Spec said | Plan does | Why |
|---|---|---|
| `profiles.education` jsonb only | Adds `profiles.highest_education education_level` | The Utdanning component compares against `jobs.education_min`; the jsonb array has no level field. The jsonb array stays for CV rendering. |
| `compute_match(job_id, profile_id)` | Adds an overload `compute_match(j jobs, p profiles)`; the uuid version is a thin wrapper | The row version is pure and testable without inserting `auth.users` rows. Recompute loops call the row version directly (one pass, no per-pair lookups). |
| `job_shortlist` "caps at shortlist_cap" | View exposes `rank` and `on_shortlist boolean` for all applicants | The employer page needs the beyond-cap rows to render "Venteliste (n)". Callers filter on `on_shortlist`. |
| RLS unspecified for `companies` | All authenticated users may `select` companies | Candidate match cards show the company name. Deliberate: company names are not sensitive. |

```bash
cat > supabase/migrations/0002_rls.sql <<'EOF'
-- Resolves the company of the signed-in employer. security definer so that
-- reading employer_users does not itself require a policy that reads
-- employer_users (infinite recursion).
create or replace function public.current_company_id()
returns uuid
language sql
stable
security definer
set search_path = public
as $fn$
  select company_id from public.employer_users where id = auth.uid()
$fn$;

alter table public.companies      enable row level security;
alter table public.employer_users enable row level security;
alter table public.jobs           enable row level security;
alter table public.profiles       enable row level security;
alter table public.match_scores   enable row level security;
alter table public.applications   enable row level security;
alter table public.interviews     enable row level security;

-- companies: readable by anyone signed in (match cards show the company name),
-- writable only by that company's employer.
create policy companies_select on public.companies
  for select to authenticated using (true);
create policy companies_update on public.companies
  for update to authenticated using (id = public.current_company_id());

-- employer_users: own row only.
create policy employer_users_select on public.employer_users
  for select to authenticated using (id = auth.uid());

-- jobs: published jobs are public to signed-in users; an employer sees and
-- manages every job belonging to their own company, including drafts.
create policy jobs_select on public.jobs
  for select to authenticated
  using (status = 'published' or company_id = public.current_company_id());
create policy jobs_insert on public.jobs
  for insert to authenticated
  with check (company_id = public.current_company_id());
create policy jobs_update on public.jobs
  for update to authenticated
  using (company_id = public.current_company_id())
  with check (company_id = public.current_company_id());
create policy jobs_delete on public.jobs
  for delete to authenticated
  using (company_id = public.current_company_id());

-- profiles: own profile, or a profile that has applied to one of my jobs.
-- This is the policy that stops anyone browsing the candidate pool.
create policy profiles_select_own on public.profiles
  for select to authenticated using (id = auth.uid());
create policy profiles_select_applicant on public.profiles
  for select to authenticated
  using (exists (
    select 1
    from public.applications a
    join public.jobs j on j.id = a.job_id
    where a.profile_id = public.profiles.id
      and j.company_id = public.current_company_id()
  ));
create policy profiles_insert_own on public.profiles
  for insert to authenticated with check (id = auth.uid());
create policy profiles_update_own on public.profiles
  for update to authenticated
  using (id = auth.uid()) with check (id = auth.uid());

-- match_scores: my own scores, or scores on my company's jobs. Employers use
-- these only for the "47 kvalifiserte matchet" count — profile details still
-- require an application. Writes happen through definer functions only.
create policy match_scores_select_own on public.match_scores
  for select to authenticated using (profile_id = auth.uid());
create policy match_scores_select_employer on public.match_scores
  for select to authenticated
  using (exists (
    select 1 from public.jobs j
    where j.id = public.match_scores.job_id
      and j.company_id = public.current_company_id()
  ));

-- applications: a candidate reads and creates their own; an employer reads and
-- updates applications on their own jobs. Only the employer changes status.
create policy applications_select_own on public.applications
  for select to authenticated using (profile_id = auth.uid());
create policy applications_insert_own on public.applications
  for insert to authenticated with check (profile_id = auth.uid());
create policy applications_select_employer on public.applications
  for select to authenticated
  using (exists (
    select 1 from public.jobs j
    where j.id = public.applications.job_id
      and j.company_id = public.current_company_id()
  ));
create policy applications_update_employer on public.applications
  for update to authenticated
  using (exists (
    select 1 from public.jobs j
    where j.id = public.applications.job_id
      and j.company_id = public.current_company_id()
  ));

-- interviews: employer manages them on own jobs; candidate may read own.
create policy interviews_select_own on public.interviews
  for select to authenticated
  using (exists (
    select 1 from public.applications a
    where a.id = public.interviews.application_id and a.profile_id = auth.uid()
  ));
create policy interviews_all_employer on public.interviews
  for all to authenticated
  using (exists (
    select 1 from public.applications a
    join public.jobs j on j.id = a.job_id
    where a.id = public.interviews.application_id
      and j.company_id = public.current_company_id()
  ))
  with check (exists (
    select 1 from public.applications a
    join public.jobs j on j.id = a.job_id
    where a.id = public.interviews.application_id
      and j.company_id = public.current_company_id()
  ));
EOF
```
